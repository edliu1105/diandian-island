## 3. 问题（按严重程度）

### Q1（中等）每次打开 app，第一次到地图时没有宝箱；地图上的"找回老朋友！"从来没说过

**现象**：宝箱按钮由 `MapV2.ensure()` 建，`MapV2.update()` 只在 `MapView.update()` 里被调；`MapView.enter()`（点"开始"）调用 `update()` 和 `MapV2.hello()` 时，`v2games.js` 还没加载（`index.html:11186` 的 `MapV2` 还是空壳 `{ update() {}, hello() {} }`），加载完以后（`v2games.js:748–749`）只补调了 `Gems.pending()`（P8 的修法），没有再调一次 `MapView.update()`。于是第一次到地图没有宝箱、没有"找回老朋友！"的招呼和宝箱晃动；要等玩完一局回地图（`Session.finish` 里的 `MapView.update()`）、关一次家长面板、或看完一张卡，宝箱才出现。`hello()` 只在 `enter()` 里调，所以地图上这句招呼永远不会说（卡册打开时说的那句"找回老朋友！"是另一处）。星空存档本应被 `w4games.js:3851` 的 `MapView.update()` 救到，但它只在 `MapView.set !== 4` 时执行，存档本来就在星空时也不执行。

**证据**：`run_fix.txt`、`run_last.txt`、`run_last_pt1snap.txt`：真实速度第一片海 / 第二片海 / 云上 / 星空、fast 模式第一片海 / 星空，进地图后轮询 6–8 秒 `#gemchest` 一直是 null、`Voice.say` 没有"找回老朋友！"；玩一局回地图或 `Parent.open(); Parent.close()` 之后宝箱 108 px 出现在右上角。截图 `shots/map_first_visit_set1_real.png`（右上角空着，只有右下角齿轮）。第 1 轮快照上同样复现（`run_last_pt1snap.txt`），所以不是这一轮引入的；第 1 轮探针 C9 正是在这里空指针崩掉而没有看出来。

**后果**：委托方要的"每天第一次打开时找回老朋友 → 开一张英雄卡"在打开 app 的那一刻没有入口，孩子看不到宝箱在跳、听不到招呼；家长想先给孩子看卡册也找不到按钮，要先玩一局。

**建议**：`v2games.js` 末尾那行补成 `if (Screens.cur === 'map' && !Session.G) { MapView.update(); MapV2.hello(); setTimeout(() => Gems.pending(), 600); }`（`update()` 里已经会调 `MapV2.update()` 和 `Gems.pending()`）；并把 `w4games.js:3851` 的条件去掉 `MapView.set !== 4`。顺手让 `pt1_cards.py` 的 C9 在进地图后立刻查宝箱。

### Q2（轻微，目前只在代码里走得到）题目进行中设教一教，孩子一直答错时等级不降

**现象**：`Teach.apply` 把 `G.level` 降下来并清了 `G.carry`，但这道（还是原等级的）题答错后 `Session.round` 又把 `G.carry = { kind, level: st.level }` 设成原等级（`index.html:2387`），下一题按 carry 出，再答错再 carry……只要孩子一直答错，题就一直停在原等级；答对一次才回到降低的等级。

**证据**：`run_fix3.txt` (2)：U4 L5，题目进行中 `Teach.set(1)`（`G.level` 变 4），接着答错两次：三道题的等级 `[5, 5, 5]`；答对一次后下一题 L3（降级 + 局内自适应）。从地图预设再进的常规路径没有这个问题：`[4, 4, 4]`。"关掉"的方向也对：关掉后答错一次下一题 L4、再答对回 L5。

**为什么只算轻微**：齿轮在 `#map` 里（`index.html:276`），游戏里没有齿轮，家长面板在游戏中根本打不开（`run_fix3.txt` (5)：游戏中和停顿中长按 1.9 秒都不开，`#gear` 矩形 0×0）。所以面板里"正在玩"那条路和 `Teach.set` 的游戏中分支现在只有测试钩子能走到，真实家长碰不到。但面板文案和 DESIGN.md 都写了"对正在玩的小游戏"，哪天真把齿轮放进游戏里，这个坑就会露出来。

**建议**：`Session.round` 里取 carry 时 `level = G.teach ? Math.min(carry.level, G.level) : carry.level`；或 `Teach.apply` 后把当前题的 `st.level` 也看作 `G.level`。另外文档里把"对正在玩的小游戏"改成和实际一致（"刚玩过的那个"），或者说明齿轮只在地图上。

### Q3（轻微）P6 的另一半：10 个推理题的讲解仍是"他选的 / 对的"两步，演示没有单独成步

**现象**：评审要点写"推理题至少要分出'他选的为什么不对 / 演示 / 对的为什么对'"。现在每步都有话了，但 22 个推理题（第二片海、云上、星空各岛第 4 关 + Z4）里，**C4、J4、D4、Z4、E4、L4、S4、T4、F4、I8 这 10 个**只有两个内容步：蓝圈 + 一句"为什么不对" → "我们一起看！" → 金圈 + 一句"为什么对"，演示（补花布的布飞进去、炼丹炉的规律、符号代换的算式）和金圈在同一步里一闪而过。另外 12 个（Q4、G4、Y4、W4、U4、K4、R4、I4、M4、N4、O4、F8）是三步或以上。

**证据**：`step_s34L.json` / `step_s12L.json`，例如 `L4 L3: 位置不对哦 蓝 | 我们一起看！ | 花布补好啦！ 金`、`S4 L3: 不是三个 蓝 | 我们一起看！ | 每次少两个！ 金`、`Z4 L3: 这个不是一家 蓝+蓝 | 我们一起看！ | 这个算式对！ 金`。截图 `shots/s34L_L4_L3_1180x820_stop3.png`（金圈的那一步，布已经补上）。

**建议**：这 10 个在金圈之前加一次 `await Step.beat(st)`（演示单独一步，说"再看一看！"或各自的一句），和 R4 / F8 / N4 一样。

### Q4（轻微）两处顺序和手感

- **U4 叠一叠的第一步是演示句**："两张叠起来是这样。" → [下一步] "我们一起看！" → [下一步] "这一格不一样。"（蓝）→ "对的是这张！"（金）。因为 `explain` 的第一句在第一次停顿之前就说了，所以第一步没有重说答错那句，"我们一起看！"反而排在演示之后，听起来是倒的（`run_more.txt` M7 真实时长 2.4 / 3.7 / 5.4 / 7.5 s）。建议 U4 的 `explain` 先 `Step.beat` 再说"两张叠起来是这样"，或把"我们一起看！"的提示放到第一次停顿之前。
- **"我们一起看！"单独一步，屏幕上没有任何变化**：112 个游戏每局都多一次点按（真实时长约 1.3 秒），家长点了"下一步"只听到一句过渡语。这是 P6 的修法带来的，能接受，但如果把这句并到第一步的末尾（第一步说"不是四个。我们一起看！"）会少一次空点。
