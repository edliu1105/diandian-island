## 发现的问题（按严重程度）

**[中等] 1 葫芦娃 L2 一笔画：绿色圆点不在线的端点上，离端点 30–51 px，越靠边越偏；船形题的两个绿点几乎叠在一起**
证据：`sheets/L2_zoom.png`（左：横屏 L3 船形，seed 2208——顶上的绿点在黑色端点的左上方，左边两个绿点几乎相碰，黑色端点露在它们右边；中：L5 两个方格，四角的绿点都在角的外侧；右：竖屏同样）；`sheets/L2.png`（横竖屏题面）；`targeted/log.json` `L2_geo_L` / `L2_geo_P`：9 个题（L3–L5、三个种子、kite / boat / house / domino / flag 五种图形）里绿点中心到线端点的最大距离横屏 30–38 px、竖屏 40–51 px，没有一个题是对齐的；`layout.json` L2 seed 2208 的 `v2` 被 `v6` 盖住 67%（横）/ 44%（竖）——两个本该分开的点被挤到一起。
原因：`MStroke.draw`（`w3games.js:1542`）的线画在 viewBox `-15 -15 130 130` 的 svg 里，svg 撑满纸（纸是 `g.s + 60` 见方），所以一个单位 = (g.s + 60) / 130 px、端点在 `paper.left + (15 + x) · 单位`；而 `MStroke.place`（`:1540`）把圆点放在 `g.x − g.s/2 + x/100 · g.s`——两套坐标只在正中间重合，到边上差 ≈ 30 px（横屏 g.s = 470）/ 45 px（竖屏 g.s = 560）。线段起点那个 4.6 px 粗的圆头就是露出来的小黑点。
影响：这一关的全部动作就是"从一个点点到下一个点"，现在要点的点和线的端点不是同一个位置；两个点挨在一起时孩子容易点错，答错后听到的却是"走不下去啦！"。
→ 圆点和线用同一套坐标（把圆点也按 `(15 + x) / 130` 放，或者 svg 的 viewBox 改成 `0 0 100 100` 并只覆盖纸的内框）。

**[轻微] 2 西游 S2 钻山洞竖屏：沙僧站在半空一块悬浮的小木板上，和要比的门隔着半个屏幕**
证据：`flow/P_S2_1ready.png`（竖屏题面：沙僧站在左上方一块棕色小木板上，三个门在底部）；横屏（`flow/L_S2_1ready.png`）他就站在门旁边的地上，又宽又高一眼可比。
影响：这一关要孩子拿人的宽和高去和门比，竖屏里人和门离得远，比起来要来回看；画面上一块凭空的木板也不像这个 app 其它地方那么讲究。
→ 竖屏把人放到门的一侧（门排两行也行），或者至少把木板画成山崖的一块平台。

**[轻微] 3 几处小的文案与揭晓**
- 分拣机重听（点头像）只重说牌子的问题和任务（"是红色的吗？/ 它会掉进哪个箱子？"，`targeted/log.json` `T1.relisten`），不重说"是就走绿色，不是走红色"；规则每节只在第一题说一次。R10 已经提过，这次开场说全了，但孩子中途忘了规则时还是没有地方能再听到。→ 重听时规则两句也带上，或把任务卡上的绿 / 红小圆点做成可点、点了说规则。
