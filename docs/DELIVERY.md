# 点点岛 · 交付说明

> 给 3 岁半到 4 岁、说中文、还不识字的孩子的 iPad 数学小岛。目标只有一个：**理解**数量与加法，而不是背诵。
> 本文如实记录：教什么、怎么用、测试结论、独立评审的分数轨迹，以及仍未关闭的问题。

## 1. 打开与安装

- 网址：**<https://edliu1105.github.io/diandian-island/>**（HTTPS，GitHub Pages）
- 二维码：`docs/qr.png`；可打印的卡片（含三步安装说明）：`docs/qr-card.png`
- iPad 安装：用相机扫码 → 在 Safari 打开 → 分享 → **添加到主屏幕** → 从主屏幕图标打开（全屏、无地址栏）。
- 离线：第一次联网打开后在地图上停留约 1 分钟（后台下载约 9 MB 素材），之后飞行模式下也能玩；家长面板“离线”一栏会显示“已就绪”。
- 真机验收：`docs/IPAD-CHECKLIST.md`（声音、静音开关、切后台、旋转、离线、手指——自动化测试无法替代的部分）。
- 更新、回滚、IP 下架：`docs/DEPLOY.md`。

**部署结果（2026-09-24，最终版本 `sw.js` VERSION `ve14a09ee`）**：仓库 <https://github.com/edliu1105/diandian-island>（组织 edliu1105 名下的公开仓库），GitHub Pages 从 `main` 根目录发布，**HTTPS 强制**（HSTS）。线上冒烟检查（`tests/smoke.py`，直接打开线上网址）：首页、sw.js、manifest、图标、角色、背景、报数 mp3 抽查均 200；WebKit（iPad 引擎）0.4 秒就绪、预缓存全部 228 个素材、六个世界各答一题无破图、零应用报错；Chromium 0.3 秒就绪、同样全部通过，断网后六个世界各答一题也无破图（34/34）。Playwright 的 Windows 版 WebKit 无法模拟离线重载，离线从主屏幕启动列入真机清单。这次线上检查还抓到一个本轮刚引入的问题：Service Worker 第一次接管页面时，页面会在地图上自己刷新一次。已在最终版本修复，抽查第 4 部分也加了对应检查。

## 2. 教什么

十二项早期数感按发展顺序分布在六个世界、24 个小游戏里（详细规格见 `docs/DESIGN.md` §1、§4）：

| 世界（等级） | 小游戏 | 认知 | 孩子亲手做的数学 |
|---|---|---|---|
| 小猪佩奇（L1–L3） | P1 溅！ | 瞬识（1–4 知觉、4–6 组块） | 看一眼泥点，床单盖上后选“几个” |
| | P2 穿！ | 一一对应 | 给每只小猪一双雨靴（多给、少给都可能） |
| | P3 收！ ⭐ | 基数 | 一个个收进箱子，箱子关上后回答“一共几个”（L2 起不报数） |
| | P4 插！ ⭐ | Give-N | 听到“插五根”，一根根插到蛋糕上再点火 |
| Bluey（L1–L3） | B1 比！ | 比较 | 找多的 / 少的 / 一样多（三种目标各有无声示范） |
| | B2 买！ | 一一对应 | 一样东西付一个币 |
| | B3 拉！ ⭐ | 守恒 | 亲手把一排拉开；爸爸当面加一块、拿一块或都不动 |
| | B4 补！ | 比较（差几个） | 补饼干直到两边一样多 |
| 葫芦娃（L1–L4） | H1 摘！ | 序数 | 沿藤摸，报“第几个”，摘指定的那个 |
| | H2 站！ | 序数 ≠ 基数 | “第三个上台” vs “三个上台” |
| | H3 分！ | 部分—整体 | 亲手把兄弟分两队，一队进山洞，问洞里几个 |
| | H4 藏！ | 部分—整体（隐藏部分） | 先亲手数宝石（牌子记下总数），隐身的六娃拿走几个，看着剩下的推出拿走了几个 |
| 汪汪队（L1–L4） | A1 派！ | 部分—整体 | 一队狗狗分两个任务，正好用完 |
| | A2 救！ | 合并 / 接着数（L4） | 两辆车救的动物合起来一共几只 |
| | A3 乘！ | 后继 / 前驱 | 亲手让狗狗进 / 出电梯（一两只），楼层尺上走一格或两格 |
| | A4 接！ ⭐ | 接着数 | 篮子里已有几只，接着把小猫吊上去 |
| 西游记（L1–L4） | X1 长！ | 接着数 | 金箍棒从几节变到几节 |
| | X2 翻！ | 接着数（数轴） | 先猜筋斗云落点，再亲手一格一格翻 |
| | X3 装！ | 凑五 / 凑十 | 选刚好装满篮子的那一枝 |
| | X4 变！ | 部分—整体（L3 起 = 十的组成） | 分身躲进水帘洞，从总数和外面剩下的推出躲进去几只 |
| 复仇者（L1–L4） | V1 集结！ | 接着数 | 战机里几位 + 传送门又来几位 |
| | V2 举！ | 十和几 | 一箱十个 + 散的几个 = 十几 |
| | V3 充！ | 凑十 | 先补满第一个仪表，剩下的倒进第二个 |
| | V4 解！ | 符号映射 | 照着密码摆出数量 / 读出数量对应的密码 |

每题：语音只说目标（≤8 个字），无声任务卡（初始 → 动作 → 目标）+ 幽灵手示范；孩子动手后出现“翻转时刻”——数学结构自己显形（分合图、十格、连线、数轴跳弧）。答错不打叉、不扣分、没有失败音：先指出差在哪，再用这一技能专属的方式带着看，然后换一道同类新题。

## 3. 怎么用

- **孩子**：点开始 → 地图上点一座岛 → 岛下四个小游戏徽章，发光的是推荐的那个（证据最少的一关）→ 玩一节（5 轮或约 150 秒）→ 星星飞回岛上的星灯，从已有数量接着报数；满十颗合成一颗大星（= 一个十）。第 3、5、10 次来到同一个世界有小故事（礼物、欢迎队、帽子），留下的装饰会一直在。
- **听不到声音**：屏幕上方出现大喇叭（出现时脉动四下，之后安静地留着，不和题目抢注意力）；点它或点头像，就在点按当下重说。
- **家长**：长按右下角小齿轮 1.6 秒 → 两道两位数加法（数字键盘输入，答错冷却 30 秒）→ 家长面板：语音诊断（测试发声、选择中文声音、“我听见了”）、每个世界的等级与**难度下限**、通过条件的进度、数字显示开关、**看图模式**（孩子听不见声音时打开：只靠听的题直接显示点阵）、全部解锁、清空进度。
- **解锁**：佩奇与 Bluey 默认开放；两者都通过后开放葫芦娃，依次往后。通过 = 四个小游戏各自“最近 7 个独立作答 ≥6 对且最后一个对”、关键题型都答对过、等级 ≥2、两次好的一节、近 12 题正确率 ≥75%。用过提示、重听、系统代做、引导题、示范题都不计掌握；参与星每轮照常给。

## 4. 测试结论

**抽查标准（委托方在 R3 后指定）**：评的是孩子最终看到、听到、摸到的东西——**以截图和实际操作为主**，不求全面，随机抽查；只有发现问题时才去读相关代码找原因；时间约为以前完整门禁的十分之一。落实为 `tests/spotcheck.py`，每次随机抽样（种子记入日志）：

1. 24 关每关随机等级答一题（判对、零报错）；
2. 每个世界随机一关用**真实指针**作答，回家按钮、成人门长按/短按；
3. 8 个随机关卡/等级/横竖屏的题面与揭晓**截图**，拼成一张图逐张目检；
4. Chromium 首访预缓存全部素材、断网后作答；
5. 待机与节奏（真实时长）：孩子不碰时每一级提示的**截图序列**和先后顺序、答对后庆典时长、地图星灯时长与点一下跳过、庆典期间帧间隔、按下到按压反馈的延迟。
6. 前后层次（`tests/depth_audit.py`，约 0.4 分钟）：24 关 × 横竖屏 × 最低/最高等级，在开始作答、出卡片、揭晓结束三个时刻，检查数字/光圈/旗子有没有被挡、卡片有没有被场景挡、要数的东西有没有被角色或卡片挡、站得近的角色有没有被远的压住；有问题的画面再截图确认。

**最终版本结果**：第 1–5 部分 **56/56 通过，用时 2.1 分钟**（种子 9140）；第 6 部分前后层次 **98/98，0 处问题**。

委托方还指出莱德的头像很奇怪：原来的头像是从全身图顶部按固定位置裁的，头发高的角色只剩头发和一只眼，右下角的小喇叭又压在脸上。现在 39 个头像统一按眼睛位置把脸居中重裁（没有眼睛数据的 8 位手工定位），小喇叭移到圆外。39 个逐个目检，并截了 6 个世界横竖屏的左上角、V1 英雄头像排确认。

前后层次是委托方看截图指出的：A2 的数字徽章和光圈被篱笆挡住，莱德被站在他身后的阿奇压住。按“这一类统一修掉”，先用第 6 部分把 24 关全扫了一遍，第一次扫出 **122 处**：

- 标注被挡 79 处；
- 卡片被场景挡 10 处；
- 前后关系可疑 33 处（其中一部分是东西放在别的东西上，属正常）。

改法是一套统一的层次（见 `docs/DESIGN.md` §8.1a），加上几处布局挪开，扫到 0 处。被标记的画面逐张截图确认过，其中一处是这次“卡片高于场景”新带出来的：P1 揭晓时飞到卡片上的泥点被卡片盖住。已改为标注，重拍确认。

更早的记录：R4 修复后的版本五个部分 55/55（种子 9127）；Service Worker 首次接管不再刷新页面之后，第 4 部分重跑 5/5（种子 9128），线上冒烟两个引擎通过。修改过程中另跑过种子 5150、7331、4242、4243。其中种子 7331 第一次跑第 5 部分有 1 项失败，原因在检查本身：H1 的场景里没有站在台上的伙伴，“应有一位伙伴看向孩子”的预期不成立，已改为“台上有伙伴才要求”，重跑通过。

## 6. 未关闭项（如实）

1. **没有拿到 APPROVE。** 计入轮次的最后一轮 R3 是 6/10；不计入轮次的 R4 是 7/10，仍为 REJECT。R3 与 R4 指出的问题之后都已改代码，但**没有独立评审确认**，也没有在最终版本上重跑完整门禁（按委托方指示停测）。最终版本只做了抽查（见第 4 节）。
2. **视觉统一性**：39 张角色图不可改画。R3 之后给生成道具做了哑光处理（去掉塑料感的大块高光，佩奇、Bluey 的道具几乎全平，55 张中改了 34 张，前后对比见 `docs/assets_sheets/A5_props_matte.jpg`），但**没有重新生成道具**：线条粗细和细节密度仍按原图，与平涂的佩奇、Bluey 相比仍略精细。R2/R3 都把“同一画师”列为扣分项，这一处理没有经过独立评审。
3. **真机未验收**：真实中文 TTS、静音开关与媒体会话、离线从主屏幕启动、真机帧率与温度，只能在 iPad 上验证，清单见 `docs/IPAD-CHECKLIST.md`（尚未回填）。
4. **Playwright 在 Windows 上的 WebKit 没有 Web Audio、不能模拟离线导航**：报数 mp3 的实际播放与 WebKit 离线启动只在 Chromium 上自动验证过。
5. **语音对象保留**：为规避 WebKit 回收朗读对象导致 `onend` 丢失，保留最近 24 个朗读对象（有上限，不随时间增长）。
6. **角色互动的上限**：角色图是整张贴纸，互动只能用整图动作（走、转、跳、击掌）加特效，没有逐肢体动画；钢铁侠面罩开合用推进器光效替代。
7. **IP**：六个 IP 的角色形象权利归原权利人，本项目按委托方要求使用其提供的图片，仅供家庭非商业用途；如需下架，见 `docs/DEPLOY.md` 的一条命令。
