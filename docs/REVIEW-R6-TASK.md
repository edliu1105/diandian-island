# 用户体验抽查评审（R6，第二世界，Fable 5.1 · high）

你是独立评审。对象：`index.html`（点点岛，给 4 岁左右、不识字的中文孩子的 iPad 数学小游戏 PWA）。这一轮只看**新做的第二世界**：孩子玩完第一世界（6 个岛）后，地图换到一片紫色的新海，7 个岛（6 个 IP 的新岛 + 新的睡衣小英雄 PJ Masks 岛），每个岛 3 个小游戏，共 21 个，由 7 种新玩法组成（分=平均分、排=找规律、称=天平、接=数字路缺数、照=对称双倍、归=分类统计、量=测量）。设计说明见 `docs/DESIGN.md` §10（可以只读这一节）。

委托方的要求：
- 玩法要和第一世界不一样；整体比第一世界稍难一点，但不要难很多。
- 进度：一开始只开第一个岛的第一个小游戏；一个小游戏玩完一次（一节）或拿到 5 颗星开下一个；一个岛的小游戏都玩过开下一个岛；这样孩子有过关感。
- 睡衣小英雄的角色由 AI 生成。

**评审方式：从用户体验角度抽查，不求全面，要快（约 20–30 分钟）。评的是孩子和家长最终看到、听到、摸到的东西；代码只在发现问题时用来找原因。截图必须亲眼看。**

重点抽查：
1. 过关感与进度：造存档或实际玩，看新海的开启、岛面板里的锁、玩完一节后“新游戏开啦”、开新岛；会不会卡住、孩子能不能看懂下一步去哪；地图左下角两片海的切换按钮。
2. 七种玩法各抽一两关真实点按（横屏 1180×820、竖屏 820×1180）：任务能不能看懂、目标够不够大、反馈和揭晓是否把数学讲清楚、答错后怎样、难度是否“稍难一点”。
3. 视觉 bug：被挡住、裁切、重叠、错位、数字看不清；睡衣小英雄角色/背景是否和其他角色像同一个画风。

工具（本目录，Python + Playwright 已装好；Windows 控制台先设 `PYTHONIOENCODING=utf-8`）：
- `tests/harness.py`：`serve()`、`new_page()`、`enter()`；钩子 `window.__go(world, game, level, {noDemo:true, seed})`（第二世界的 world 为 `peppa2 bluey2 pjmasks paw2 huluwa2 xiyou2 avengers2`，小游戏 `Q1-3 C1-3 J1-3 D1-3 G1-3 Y1-3 W1-3`，level 1–5）、`window.__next('right')`、`window.__gesture(g,p)`、`window.__q`、`Store`、`W2`、`MapView`。
- 造存档：`LIVE().forEach(w => Store.w(w).stars = 10); Store.s.finaleSeen = true; Store.save()` 后刷新，即第一世界全部过关。
- `python tests/test_w2.py`（第二世界功能检查）、`python tests/depth_audit.py`（前后层次）。
- 可以自己写短小的 Playwright 脚本截图，用 Read 查看。

不要修改应用代码。结果写到本目录 `REVIEW-R6.md`（中文）：总体结论（2–3 句）；问题按严重程度排序 `[严重|中等|轻微] 编号 描述（证据：截图/步骤）→ 建议`；抽查了什么；`SCORE: n/10`（9 = 顶级付费儿童应用水准；7–8 = 扎实但有“做出来”的痕迹）；最后一行 `VERDICT: APPROVE`（≥9 且无严重问题）或 `VERDICT: REJECT`。
