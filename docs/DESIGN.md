## 1. 教学法路径

### 1.1 十二项认知 → 24 个小游戏

| # | 认知 | 小游戏（世界·编号·动词·题型 kind） |
|---|---|---|
| 1 | 瞬识 | P1「溅！」`sub`（1–4 知觉）、`chunk`（4–6 组块，L3） |
| 2 | 一一对应 | P2「穿！」`pair`；B2「买！」`match` |
| 3 | 基数原则 ⭐ | P3「收！」`card`（玩具进箱后只能靠自己数到的最后一个数；L2 起不报数）；H2 的 `card` 题 |
| 4 | Give-N ⭐ | P4「插！」`giveN`；H2 `card`、A1 `split2`、V4 `n2q` 中的“取出正好 N 个” |
| 5 | 比较 | B1「比！」`more`/`less`/`same`；B4「补！」`diff`（差几个，含已相等） |
| 6 | 守恒 | B3「拉！」`same`/`add`/`remove` 三类各占 1/3 |
| 7 | 序数 | H1「摘！」`ord`；H2「站！」`ord` vs `card` |
| 8 | 部分—整体 | H3「分！」`selfsplit`（亲手分两队、藏起一队）；H4「藏！」`hidden`（独立检验，看不到拿走过程）；A1「派！」`split2`/`rest` |
| 9 | 合并 Count-All | A2「救！」`all`（L1–L3） |
| 10 | 接着数 Count-On ⭐ | A2 `on`（L4）；A3「乘！」`plus`/`minus`（后继、前驱）；A4「接！」`on`；X1「长！」`target`；X2「翻！」`line`；V1「集结！」`on` |
| 11 | 凑十 / 十和几 | X3「装！」`five`（L1）/`ten`；X4「变！」`hidden`/`ten`；V2「举！」`build`/`name`；V3「充！」`split10` |
| 12 | 符号映射 | V4「解！」`n2q`/`q2n`（数字开关关时为 `d2q`/`q2d`，单独记录） |

### 1.2 两个阶段
- **还不会数数**：佩奇、Bluey（默认开放）。L1 数值 1–3，全程报数回声与徽章；L2 起逐步撤掉报数（孩子自己数）。
- **已会数数/认数字**：葫芦娃起逐个解锁；家长可“全部解锁”并为每个世界设难度下限（L3/L4 直接进入宏步骤与结构化数量）。

### 1.3 支架递减（同一关不同等级）
| 等级 | 点数回声（计数通道） | 徽章 | 浮出总数 | 操作形态 |
|---|---|---|---|---|
| L1 | 有 | 数字/点 | 有（仅 P3 等“数完问一共”的关不浮出，避免泄露） | 逐个 |
| L2 | 只在“点数本身不是答案”的关保留 | 有 | 无 | 逐个 |
| L3 | 无（只有音高与“叮”） | 有 | 无 | 逐个或选择 |
| L4（葫芦娃起） | 无 | 有 | 无 | 宏步骤：选捆、选条、整组 |

### 1.4 防猜与防模式匹配（R1-J02、G01、G07、G08）
1. **位置袋**：三选一的正确位置每 3 题 0/1/2 各一次。固定点同一位置 → 任意连续 7 题最多对 3 题。
2. **大小袋（发牌制）**：每题先从大小袋发一个名次（最小/中间/最大），再生成题目，直到正确答案能取这个名次（范围两端取不到时重新出题；实在取不到，这个名次留到下一题先发）。`test_generators.py` 实测每关每级三种名次各 33.3%；“永远选最小/中间/最大那张”只能对 1/3。数量类干扰项允许 0（“一个也没有”）和略大于题域的数，保证两端也能均衡。
3. **语义袋**：判断题的正确答案类型（布鲁伊多 / 宾果多 / 一样多；守恒的不变/加/减；B4 的差 0/1/2）均衡出现；“永远选一样多”“永远选布鲁伊”只能对约 1/3。
4. **题型必须各自通过**：世界通过要求每关的关键 kind 都有无提示答对证据（见 §6）；混合平均分不能替代。
5. **测试**用 7 种固定策略（固定位置 ×3、永远选最小/中间/最大、永远选“一样多”、永远选第一个角色、随机×3 个种子）各跑数百题，断言不升级、不解锁。

### 1.5 反模式对照
| 反模式 | 本设计 |
|---|---|
| “3+2=?”四选一 | 只有“一共几个”类问题用 3 张卡；Give-N、配对、分派、凑十、解码都是构造作答。算式只在翻转时刻作为结果的名字浮现。 |
| 语音念结论 | 题面语音只说目标；结论只在作答后说。V4 独立评估时语音**不说数字**（“照着密码放！”），作答后才读出。 |
| 文字出题 | 零文字：语音 + 无声任务卡（初始—动作—目标三格，每个题型分支各一张）+ 幽灵手。 |
| 错误惩罚 | 无红叉/扣分/失败音/倒计时；≤1.5 s 指出差在哪，然后技能专属纠错、换同构新题。 |
| 换皮 | 每个世界一条主线，机制来自角色能力（§3）。 |
| 重复劳动 | 预算按“手势路径、纯点按路径、纠错路径”三条分别核算（§4 每关写明），测试锁死。 |
| 能被猜过 | §1.4 + §6。 |
| 系统替孩子数 | 被数物体不带编号，徽章只在孩子点到时出现；尺子类（云朵、楼层尺、仪表格、金箍棒刻度、显示屏）永久带数字。 |

## 2. 世界观、地图与一节的流程

- **故事**：大海上的“点点岛”，六群好朋友各有一件要“数一数”才能办成的事。每帮完一件事得一颗星，飞回这座岛的**十格星灯**；满十颗合成一颗**大星**挂在岛旗旁（十个一 = 一个十）。六座岛都通过掌握门后，中央**灯会岛**亮起：39 位角色上台、烟花、合影（大结局，可随时重看）。
- **地图**：俯视大海 + 7 座岛屿贴纸 + 虚线小路（按认知顺序）。岛上站着主角（呼吸、眨眼、偶尔挥手），旁边是十格星灯与大星；通过后插小旗。未开放的岛盖着飘动的云，点它 → 云晃一下 +“先去这里玩吧” + 手指向可玩的岛。
- **岛面板**：点开放的岛 → 岛放大，四枚小游戏徽章环绕（推荐的一枚发光）；点徽章开始；点空白处收起。
- **加载**：已缓存时 ≤400 ms 转场；未缓存时显示主角奔跑的等待画面，直到本节背景与道具就绪（最多 6 s）。
- **开场**：0.8 s 大字动词横幅 + 音效 + ≤8 字目标语音 + 幽灵手演示手势轨迹（不点任何答案目标），孩子任何输入立即接管。
- **首次示范**：第一次玩某关，幽灵手把一整道题从头做完（含提交与翻转），不计分，可点击快进。
- **结束**：≤2.5 s 小庆典（可快进）→ 转场回地图 → 星星一颗颗飞进星灯，从已有数量接着报数（例：已有 7 颗 → “八、九、十”→ 十颗合成大星）→ 地图安静下来，推荐的岛轻轻发光。没有弹窗。
- **大房子**（左上角，固定位置）随时回地图，无二次确认；**头像**（大房子右侧）= 重听题目（算提示）。

## 4. 24 个小游戏规格

**通用**
- 预算：L1 ≤5；L2/L3 ≤7；L4 ≤4 个宏步骤。每关给出三条路径的操作数：**手势路径 / 纯点按路径 / 纠错中孩子需要做的操作**（提交都计入）。
- 三选一卡：数字开 → 大数字 + 小点阵（点阵排布与题面排布坐标不同）；数字关 → 只有点阵。点径 ≥14 单位、点距 ≥6、描边墨线；十以上 = 一根十格条 + 点。
- 提交按钮：舞台右下固定位置、统一圆形贴纸造型，图标随关卡主题；首次示范里幽灵手会按一次它。
- 每句语音 ≤8 字（不计标点）；计数用“二”，量词用“两”。
- “同构新题”= 同 kind、同等级、参数不同（题面指纹不同）。

### 世界 1 · 小猪佩奇（peppa，L1–L3）环境声：细雨 + 鸟

#### P1「溅！」看一眼有几个泥点 · kind `sub`/`chunk`
- **目标**：#1 瞬识。**能力**：跳泥坑必溅泥点；猪妈妈把床单翻过去要洗 = 一闪而过。
- **场景**：`garden`；前景：泥坑、晾衣绳 + 白床单（SVG，按背景锚点定位）。跳的人轮换佩奇 / 乔治 / 猪爸爸（溅得最大）；猪妈妈翻床单。
- **动作阶段**：在跳的人身上下滑（点按：点他）→ 跳、溅、泥点落在床单上显示 T → 猪妈妈翻床单盖住 → 三张卡。动作阶段的提醒只催“跳一下”，不涉及答案，不计提示。
- **参数**（数量都用袋子均衡，大小名次用大小袋）：L1 n∈1–3，T=1000 ms，选项{1,2,3}；L2 n∈2–4，T=900，选项按大小袋取 {n,n+1,n+2}/{n−1,n,n+1}/{n−2,n−1,n}；L3 `chunk` n∈4–6 由两个小组块构成，T=900。泥点布局每题随机（散点/一行/两团），与卡片排布坐标不同。
- **操作**：手势 2 / 点按 2 / 纠错 0。
- **翻转**：床单翻回，泥点缩成组块并套软圈（“三和二”），再一颗颗飞进所选卡片的点里。
- **纠错（组块闪现）**：床单翻回，组块依次亮起并说“两个”“三个”→“一共五个”，正确卡片轻跳。
- **任务卡**：[小猪 ↓] → [床单上的泥点 + 👁] → [点卡]。
- **语音**：开场「跳泥坑，看泥点！」；题面「几个泥点？」；总结「三个泥点！」/「三和二，五个！」。

#### P2「穿！」每只小猪一双雨靴 · kind `pair`
- **目标**：#2 一一对应。**能力**：跳泥坑一定要穿雨靴。
- **场景**：`porch`。接收者：佩奇、乔治、猪爸爸、猪妈妈、泰迪熊、恐龙先生（按等级取前几位，站位高低错落）。
- **动作**：拖一双雨靴到某人脚下（点按：点某人 → 靴架飞来一双；再点一次会再给一双，“多给”是可能犯的错）；点某人脚下的雨靴 → 飞回靴架；靴架已空时点没有雨靴的人 → 靴架晃一晃（“没有了”），要先从多拿的人那里拿回一双。提交：点泥坑按钮（大家去跳泥坑）。
- **参数**：L1 2 人 + 靴 3 双；L2 2–4 人（袋子轮换）+ 5 双；L3 4–5 人 + 7 双。
- **操作**：L1 3/3/0；L2 4/4/0；L3 6/6/0。
- **判定**：每人恰好一双（不论总数）。
- **翻转**：大家一个接一个跳进泥坑，每跳一个报一个数，最后一个大 SPLASH；人与靴之间亮出连线“每人一双”。
- **纠错（一一对应）**：系统逐个画“人—靴”连线并报数；缺靴的人脚下闪黄；多的那双自己跳回靴架。
- **任务卡**：[小猪][雨靴] 1 对 1 链环 → [泥坑按钮]。
- **语音**：开场「穿雨靴，跳泥坑！」；题面「每人一双！」；总结「每人一双，正好！」。

#### P3「收！」收玩具，箱子里一共几个 · kind `along`（L1，教学）/`card` ⭐
- **目标**：#3 基数原则。**能力**：猪妈妈说收玩具；进了箱子就看不见了。
- **场景**：`bedroom`。乔治（玩具主人）、佩奇、猪妈妈（发问）。
- **动作**：在玩具上朝箱子一甩（走廊判定；点按：点玩具）→ 玩具落进箱子（箱前板挡住）→ 全部进箱 → 三张卡。
- **L1 `along`（教学，永不计证据）**：每进一个帮手报数 + 大数字；全部进箱后玩具**换一种排法**跳回地面，才问“玩具一共几个？”（此刻不说任何数字）。
- **L2+ `card`（关键题型）**：收玩具只有“叮”和音高，**不报数**；箱子关着、提问前不说任何数字 → 只有自己数到的最后一个数能回答。
- **参数**：L1 n=2–3；L2 n=3–5；L3 n=4–6（全部逐个，不预置，不接着数）。
- **操作**：L1 ≤4/≤4/0；L2 ≤6/≤6/0；L3 ≤7/≤7/0。
- **翻转**：箱子弹开，玩具跳出排成一行（顺序与放入不同），最后一个的徽章长大成一个圈套住全部——“数到四，一共四个！”；接着把它们**换个排法**再亮一次同一个数——“换个排法，还是四个！”。
- **纠错（一起重数）**：玩具出来排好，系统逐个点亮报数，邀请孩子跟着点；强调最后一个数并套圈。
- **任务卡**：[玩具] → [箱子] → [点卡]。
- **语音**：开场「收玩具啦！」；题面「箱子里一共几个？」；总结「数到四，一共四个！」。

#### P4「插！」生日蜡烛 · kind `match`（L1）/`giveN` ⭐
- **目标**：#4 Give-N。**能力**：过生日插蜡烛。
- **场景**：`kitchen`；蛋糕按背景桌面锚点放在桌上；寿星轮换戴生日帽。
- **动作**：点蜡烛盒 → 飞出一根插到蛋糕上（一排站，每加一根整排让位，火苗互不遮挡；插多了才出现交错第二排）；点蛋糕 → 最后一根回盒。提交：**按住**火苗按钮 0.5 s（点按：点一下）。手势示范就是“点盒子”，与真实输入一致。
- **L1 `match`**：任务卡上 N 的点阵直接可见（学任务，可对着点阵一一插）。**L2+ `giveN`**：N 只用语音给出；任务卡上是数字 + 藏在“？”翻盖下的点阵——第二级提示或检测到失声时翻盖自动打开（打开即受辅助；失声时本题不计证据），听不见的孩子也能完成。
- **参数**：L1 N=1–3（报数）；L2 N=2–5（不报数，只有“叮”）；L3 N=4–6（不报数）。蜡烛盒总有 N+3 根以上。
- **操作**：L1 ≤4/≤4/0；L2 ≤6/≤6/0；L3 ≤7/≤7/0。
- **判定**：蛋糕上的蜡烛 = N。
- **翻转**：蜡烛一根根点亮并报数复核 → 生日小调 → 寿星一吹 → N 缕烟升空聚成 N 个点（数字开时再聚成数字）。
- **纠错（Give-N）**：多了 → 多的一根根跳回盒子；少了 → 蛋糕上浮现 N 个光圈，空圈闪黄，系统补上并接着报数。
- **任务卡**：[数字 N + 点阵（L2+ 在翻盖下）] → [蜡烛 → 蛋糕] → [火苗]。
- **语音**：开场「乔治过生日！」；题面「插三根蜡烛！」；总结「三根，正好！」。

### 世界 2 · Bluey（bluey，L1–L3）环境声：虫鸣 + 鸟

#### B1「比！」谁的多？ · kind `more`/`less`/`same`
- **目标**：#5 比较，数量对抗面积与间距线索。
- **场景**：`yard`。布鲁伊、宾果各端一盘；妈妈发问；爸爸起哄。
- **动作**：点多的那盘 / 少的那盘 / “一样多”按钮。姐妹左右位置每题随机。
- **参数**（语义袋：布鲁伊多 / 宾果多 / 一样多 各 1/3；“多”“少”问法各半，L1 只问“多”）：L1 各 1–4，差 ≥2 或相等，同样大小；L2 各 2–5，差 ≥1 或相等，50% 题“少的那边东西更大”；L3 各 4–7，差 1 或相等，一边摊开一边挤紧。
- **操作**：1/1/0。
- **翻转**：两盘东西各排一行对齐，一对一牵线，落单的发光跳动——“宾果多一个！”。
- **纠错（配对）**：同上放慢，落单的闪黄并数出“多了两个”；“一样多”时全部配上、没有落单。
- **任务卡（每个目标一张，无等号）**：一个**不同于本题**的小例子——两个小盘（3:2 或 2:2）和一个“一样多”小按钮，动画手指反复点在“多的那盘 / 少的那盘 / 一样多按钮”上，停在对应的选择动作上。第二级提示：真实场景里的手依次经过两盘和“一样多”，不替孩子选。
- **语义袋**：L1 题型袋为 {多, 多, 一样多}，布鲁伊多 / 宾果多 / 一样多各 1/3。
- **语音**：题面「谁的多？」/「谁的少？」；总结「宾果的多！」/「一样多！」。

#### B2「买！」一样东西一个币 · kind `match`/`remember`
- **目标**：#2 一一对应造等集 → L3 用数来记住多少。
- **场景**：`shop`（纸箱小店）。宾果当店主，布鲁伊来买；妈妈看着。
- **动作**：拖硬币到柜台垫（点按：点钱罐滑出一枚）；点柜台上的币 → 退回。提交：按铃。
- **参数**：L1 2–3 样（篮子一直打开）；L2 3–5 样（打开）；L3 `remember` 3–5 样：孩子先点数每样东西（徽章），**数完篮子自动盖上**，然后从三摞硬币（1–5 枚，看得见）里选一摞给宾果（选择即提交）。
- **操作**：L1 ≤4/≤4/0；L2 ≤6/≤6/0；L3 ≤6（点数 ≤5 + 选一摞）/≤6/0。
- **判定**：币数 = 东西数。
- **翻转**：收银台把硬币一枚枚跳到每样东西上配对，宾果装袋递过去。
- **纠错**：配对连线；没付钱的闪黄，多的币跳回钱罐。
- **任务卡**：`match` [东西][币] 1 对 1 → [铃]；`remember` [东西 → 篮子盖上] → [一摞币]。
- **语音**：开场「我们玩开小店！」；题面「一样东西一个币」；总结「四样四个，正好！」。

#### B3「拉！」这样公平吗？（守恒）· kind `same`/`add`/`remove` ⭐
- **目标**：#6 守恒——只有加进去/拿走才改变数量。
- **场景**：`playroom`。两行积木（布鲁伊一行、宾果一行，先一一对齐）。
- **流程**：三类各占 1/3（语义袋）：`same` 只变形；`add` 爸爸**当面**塞进一块再变形；`remove` 爸爸**当面**拿走一块再变形。变形由**孩子亲手**拉开（或推挤）一行；然后爸爸说“宾果的多了！”→ 三选一。变形方向与真实多少相反的题占 `add/remove` 的一半以上。
- **动作**：拉（拖一行的末端外拉/内推；点按：点那一行，自动拉开）→ 点答案。
- **参数**：L1 各 3–4 块；L2 各 4–5；L3 各 5–6。
- **操作**：2/2/≤6（纠错里孩子点亮着的那块，连线到对面；5 秒手指提示、9 秒才由系统代做并记录；一旦代做过一对，其余各对以 0.7 s 节奏示范完，不再每对等 9 秒。配对期间快进层关闭，孩子的手指直接落在方块上——R3 前真实指针测试发现快进层曾挡住配对）。
- **翻转**：`same`：拉长的一行像手风琴收回，一对一连线——「没加没拿，一样多！」；`add`：连线后多出的那块亮起——「爸爸加了一块！」；`remove`：连线后空出的位置亮起——「爸爸拿走一块！」。
- **纠错（守恒·亲手配对）**：孩子依次点长行的每一块，它与对面一块连线；按类别说出对应结论（不会把增减题说成一样多）。
- **任务卡**：[两行对齐] → [一行被拉长 ↔（或手放进/拿走一块）] → [两边配对后看谁有落单]。
- **语音**：开场「这样公平吗？」；爸爸「宾果的多了！」；题面「谁的多？」；总结见翻转。

#### B4「补！」还差几个才公平 · kind `diff`
- **目标**：#5 比较中的差（含差 0）。
- **场景**：`kitchen2`。妈妈拿饼干罐、宾果（少的或一样的）、布鲁伊、爸爸的大拇指按钮。
- **动作**：L1–L2 **转**：绕罐子画圈倒饼干，每 60° 倒出一块、反转收回（点按：点罐子倒一块；点宾果盘里的饼干收回）；提交：点大拇指。L3：三个纸袋各装 0–3 块（看得见，袋子“空袋”也是选项）→ 点/拖一个给宾果（选择即答案）。
- **参数**（差值袋：0/1/2 均衡）：L1 布鲁伊 2–3，差 0–2；L2 布鲁伊 3–5，差 0–2；L3 布鲁伊 4–7，差 0–3。
- **操作**：L1 ≤3/≤3/0；L2 ≤3/≤3/0；L3 1/1/0。
- **判定**：宾果最终数量 = 布鲁伊。
- **翻转**：两盘一对一连线，新补的发光并说“补了两个”（差 0：「本来就一样多！」），姐妹抱在一起。
- **纠错（差）**：连线后布鲁伊那边落单的闪黄 =“还差两个”；多倒的跳回罐子。
- **任务卡**：[布鲁伊的盘][宾果的盘] → [罐子 → 宾果 或 什么也不加] → [两盘全部配上]。
- **语音**：开场「要公平哦！」；题面「宾果还要几个？」；总结「补两个，一样多！」/「本来就一样多！」。

### 世界 3 · 葫芦娃（huluwa，L1–L4）环境声：山风 + 鸟

#### H1「摘！」第几个葫芦熟了 · kind `ord`
- **目标**：#7 序数。**能力**：七个葫芦从藤根按顺序成熟。
- **场景**：`vine`；藤蔓 SVG + 绿葫芦位图，**摘之前全是同样的绿色**；爷爷站在藤根。
- **动作**：手指沿藤滑，碰到的葫芦亮起并报**它自己从藤根数起的位置**（“第三”），在目标上松手 = 摘（点按：直接点葫芦）。从中间开始、往回滑、重复经过，每个葫芦说的都是同一个序数——序数属于位置，不属于“摸了几个”。
- **参数**：L1 3 个、第 1–3、藤根在左；L2 4–5 个、第 2–4；L3 5–6 个、第 2–5、藤根左右随机；L4 7 个、第 3–7、藤根随机。
- **操作**：1/1/0。
- **翻转**：葫芦开花，第 k 个位置的葫芦娃跳出；从藤根一路亮到它：“第一、第二、第三！”，头上插序数小旗。
- **纠错（从起点数）**：幽灵手从藤根滑到目标并报序数；点错的那个挂上它自己的小旗。
- **任务卡**：[爷爷/藤根] → [沿藤的箭头] → [小旗 k]。
- **语音**：开场「葫芦熟啦！」；题面「摘第三个！」；总结「第三个，是三娃！」。

#### H2「站！」第三个 ≠ 三个 · kind `ord`/`card`
- **目标**：#7 与 #3 分离。
- **场景**：`meadow`；前景石台（独立元素）。兄弟**每题随机排列**（第三个是谁不固定），爷爷站在队头一端，队头是起点。
- **流程**：爷爷随机说「第三个娃，出来！」或「三个娃，出来！」（题型袋均衡）→ 请娃上石台 → 提交。
- **动作**：拖娃上石台（点按：点娃上台/下台）。
- **参数**：L1 3–4 人、k=1–3；L2 5 人、k=2–4；L3 6–7 人、k=2–5；L4 7 人：序数 k=4–7、基数 k=2–3（纯点按也在 4 步内）。
- **操作**：序数 2/2/0；基数 k+1（L1≤4、L2≤5、L3≤6、L4≤4）。
- **判定**：序数 → 台上只有第 k 位；基数 → 台上恰好 k 位。
- **翻转**：序数：从爷爷起一路亮到第 k 位，插小旗；再浮出前 k 位的虚影——「第三个只一个」「三个是三个娃」（两句）；基数：台上 k 位手拉手，头顶亮出点卡 k。
- **纠错**：左右并排演示“第三个”（数位置，只站出一个）与“三个”（一、二、三，三个一起站出）。
- **任务卡**：序数 [小旗 k] → [一个娃上台]；基数 [点卡 k] → [k 个娃上台]。
- **语音**：题面「第三个娃，出来！」/「三个娃，出来！」；总结「第三个只一个」/「三个娃，一二三！」。

#### H3「分！」兵分两路，一路进山洞 · kind `in`/`out`（R3 后）
- **目标**：#8 部分—整体的学习阶段：**孩子亲手**把整体分成两份，其中一份看不见。
- **能力**：兄弟兵分两路救爷爷——一路走山路（留在外面），一路钻山洞。
- **场景**：`cave`（洞口是独立前景元素）。爷爷发令。
- **流程**：任务卡与语音给出整体“一共 N 个娃！”→「送几个进山洞？」→ 孩子点（或拖）一个娃，他**走进洞里看不见**；点洞口 = 最后进去的那个回来（两边都至少一个）→ 点火把 → 洞口一亮 → 两种问法由题型袋交替：`in`「洞里有几个娃？」（洞里的看不见）；`out`：洞里的娃出到洞口，外面的娃**去巡山**离开画面 →「巡山的有几个？」（答案 = 整体 − 洞里）。三选一。分拆本身就是数学动作：此阶段的任何提示都使本题受辅助。
- **掌握要求分法多样**（R3-J01）：H3 的单关门除 7 题中 6 对外，还要求最近 7 个正确证据里洞里部分至少 3 种、外面部分至少 2 种；孩子连续两次同一种分法时，下一题开头爷爷说“这次换个分法！”。
- **参数**：L1 N=3；L2 N=4–5；L3 N=5–6；L4 N=7（点某个娃 = 他和他后面的一起进洞，一步完成一段）。
- **操作**：L1 ≤4；L2 ≤6；L3 ≤7；L4 3。
- **翻转**：洞里的娃出来站在洞口，两队分别套圈——「三和四，合起来七个」。
- **纠错（部分—整体·数到整体）**：先数外面的，洞里的娃一个个探出来接着数到 N——“洞里有四个”。
- **任务卡**：[N + 点阵] → [娃 → 洞] → [洞 ?]。
- **语音**：开场「兵分两路！」；「一共七个娃！」「送几个进山洞？」；题面「洞里有几个娃？」；总结「三和四，合起来七个」。

#### H4「藏！」六娃拿走了几个 · kind `hidden`
- **目标**：#8 独立检验：整体已知、看得见一部分，**看不到拿走的过程**，求藏起的部分。
- **能力**：六娃隐身，溜进蛇精宝库。
- **场景**：`treasure`。蛇精数宝石、蝎子精打瞌睡（点他会醒）。
- **流程**：L1–L2 孩子先点数宝石（整体）；L3–L4 蛇精说“我有七颗宝石”，宝箱上的尺子显示 N → 一团**闪光的云**罩住整堆宝石（看不见里面）→ 云散开，一些宝石不见了、剩下的**重新摆放**（不能靠位置空缺数）→「六娃拿了几个？」三选一 → 孩子在闪光处擦一擦，六娃现身。
- **动作**：擦（区域擦过；点按：点闪光）。
- **参数**：L1 N=3，拿 1–2；L2 N=4–5，拿 1–3；L3 N=5–7，拿 2–4；L4 N=8–10，拿 2–5。
- **操作**：L1 5（点数 3 + 选 + 擦）/5/0；L2 ≤7/≤7/0；L3 2/2/0；L4 2/2/0。
- **翻转**：六娃现身放回宝石，“看得见的”与“拿走的”两团套圈再并成大圈——「五是三和二！」。
- **纠错（求部分·数到整体）**：先数看得见的，再在六娃处浮出虚线宝石接着数到 N——“拿了两个”。
- **任务卡**：[N 颗宝石] → [闪光云罩住] → [剩下的] → [点卡？]。
- **语音**：开场「六娃，隐身！」；蛇精「我的宝石呢？」；题面「六娃拿了几个？」；总结「五是三和二！」。

### 世界 4 · 汪汪队（paw，L1–L4）环境声：海浪 + 海鸥

#### A1「派！」一队分两个任务 · kind `split2`/`rest`
- **目标**：#8 部分—整体（整体被分成两份，两份正好用完整体）。
- **场景**：`control`；大屏两个任务面板（SVG）。莱德发令；狗狗们是整体。
- **流程**：`split2`（L1–L2）：两个任务都标出需要几只（a、b，a+b = 队伍数）→ 孩子派狗狗 → 爪印按钮出发。`rest`（L3–L4）：只标火灾要 a 只，“剩下的去洪水”→ 先**预测**洪水几只（三选一，这是首答证据）→ 然后孩子自己派 a 只去火灾（验证，不计分），剩下的自动去洪水。
- **动作**：拖狗狗到面板；或先点一只狗狗（它发光）再点面板；只点面板 = 下一只等待的狗狗上去；点任务队里的狗狗 = 回来。**游戏从不替孩子决定去哪个任务**（R2 前版本“点狗狗自动凑够火灾数”已删除）。

- **翻转**：`n2q` 锁上的数字“碎”成 n 个光点，一颗颗飞进水晶一一对应，宝库大门打开——「七，就是七个！」；`q2n` 箭射中后靶上的数字化成 n 个点与箭一一对应。
- **纠错（符号）**：数字旁浮出它的点卡（“七是五和二”），与水晶/箭一一连线；缺的闪黄、多的跳回。
- **任务卡**：`n2q` [数字 7] → [水晶 → 锁] → [爪印]；`q2n` [箭袋] → [靶 ?]。
- **语音**：开场「黑豹的宝库！」；题面「照着密码放！」/「射哪个靶？」；总结「七，就是七个！」。

## 5. 每题契约与状态机

```
一轮 = 首题 →（对）翻转 + 表扬 + 星 → 下一轮
            →（错1）≤1.5s 指出差在哪 → 技能专属纠错 → 同构新题（复测）
                   →（对）→ 下一轮
                   →（错2）指出差在哪 → 纠错 → 引导模式（系统带着做对，计提示）→ 星 → 下一轮
```
- 本轮错误计数生成复测题时**不重置**；一轮最多错 2 次，第 3 题一定被带着做对。
- 同一世界连续两题的“题面指纹”（kind + 参数）不同，跨节也记。
- **题目状态机**：`phase: setup → act → ready → input → judging → (correcting | reveal) → praise → done`。每题一个 `st`，带单调递增的 `gen`；所有异步序列开头 `const my = st`，每个 await 后 `if (!alive(my)) return`。**提交只能发生一次**（`st.submitted` 一次性标记）；快进与自然完成走同一条 await 路径（快进只是让动画与等待立即结束），不存在第二条完成路径。
- **输入锁**：非 `act/ready/input` 阶段的作答手势一律忽略（按压反馈仍有）；快进手势例外。答案一旦提交，答案卡即失效（翻转里重新开放的“亲手验证”步骤只接受该步骤自己的目标）。
- **异步步骤出错**：手势或计时器启动、题目循环不直接等待的异步步骤（如 H3 点火把进洞、H4 定时的“六娃拿走”）若抛错，本题按独立的 `error` 结果结束（不给星、不记证据、`console.error`），下一题照常出现；连续 3 次出错本次结束回地图（`test_faults.py`）。孩子不会停在一个没有卡片、没有提示的画面里。
- **资源所有权三级**：应用（语音看门狗、可见性监听、Service Worker）/ 世界节（环境声、角色待机计时、舞台监听、预加载请求）/ 题目（计时器、动画、指针捕获、提示、音频源）。换题、回地图、旋转、切后台都会让旧的题目作用域失效：计时器清除、动画取消、指针捕获释放、过期的解码结果按请求序号丢弃。

### 5.1 提示与恢复（计提示 = 本题不计掌握）
全部时间按**应用时钟**（切后台时停止），从“题面说完 / 孩子最后一次**自己的**有效操作”起算，**绝对截止时间**（系统代做不重置计时）：
| 时间 | 动作 |
|---|---|
| 5 s | 重说目标 + 工作区微光 |
| 10 s | 幽灵手演示手势（B1：依次经过三个选择；P4：点盒子；翻盖类同时打开点阵） |
| 15 s | 手指点在下一步正确操作上 |
| 20 s，之后每 1.6 s | 系统**带着做一步**，连贯示范到完成——锚定不漂移；多步题也在 40 秒内结束（R3-U05）；孩子一触碰立即收回控制 |
- **任何一种**帮助都使本题受辅助：以上各级、重听（点头像）、两次手势失败后的重教、B3 纠错里的代做。`act` 阶段若本身是数学操作（H3 亲手分拆、H4 先数宝石、A3 亲手让狗进出电梯）同样计辅助；纯准备动作（P1 起跳、A2 吹哨、X4 吹毫毛）的提醒不影响证据。每题保存辅助时间线。
- 完全不操作：每题必然由帮手完成（不计证据）；连续两题都这样 → 本次结束回地图。
- 单一注意力调度：提示 > 角色小表演 > 彩蛋。

### 5.2 自动往下走与快进
答对 → 翻转 → 表扬 → 停 1.2 s → 自动下一题。演示/揭示/停顿期间点屏幕任意处 = 快进：结束当前动画、清掉等待、只说总结句。

### 5.3 一节的时长
5 轮或约 150 s（先到先止，至少 3 轮）。一轮最长（首题 + 两次复测 + 纠错）约 70 s；超过 150 s 时当前轮结束即收尾。

### 5.4 中途旋转 / 回地图 / 切后台
- 旋转：中止进行中的手势（拖动物弹回、按住清零），场景按新方向重排，再统一重排本题的任务卡、完成按钮、答案卡，最后调用各关 `relayoutQ`；题目状态与语音保持（`test_rotate.py`）。
- 回地图：只销毁**这一次**会话；其作用域发出的所有等待与动画承诺永不完成，旧流程停在下一个 await，不可能再写界面、说话或记账；语音 `hush('leave')`，计数通道 `stop()`，环境声淡出。
- 切后台：应用时钟停止（提示与会话时长不计后台）、手势中止、AudioContext 挂起；回前台 resume 语音、WebAudio 与无声 audio。

## 6. 掌握证据、升降级与解锁（R1-J01/J02）

### 6.1 数据（每个世界）
```
level, floor                  // 隐藏等级、家长下限
win[]                         // 升降级滑动窗口：本等级的证据 {g, ok}，换级清空
hist[]                        // 最近 12 个证据 ok 位，跨等级，永不因换级清空
g[game] = {n, c, bits[], k:{kind: 答对数}}   // 按小游戏、题型分别记录
log[]                         // 最近 40 次作答（含提示/引导/示范标记），供家长面板区分“已掌握 / 证据不足”
mastery, windows, stars, unlocked, cleared, rot/lastKey/visits ...
```
- **证据**：新题（首题或复测题）+ 本题未用任何提示 + 首次作答。引导题、示范题、提示过的题都不是证据（但会进 `log`）。

### 6.2 规则
- **升级**：`win` 至少 7 个；最近 7 个 ≥6 对；最后 3 个全对；这 7 个来自 **≥2 个不同小游戏**。
- **降级**：`win` 最近 4 个 ≤1 对，或连续 3 轮以“系统带着做”收尾 → 降一级（不低于 floor），清空 `win`。
- **会话窗口**：本节证据 ≥4 且正确率 ≥0.75 → `windows+1`（每节最多一次）。
- **本世界通过（= 解锁下一世界）**，全部同时成立：
  1. `level ≥ 2`；`windows ≥ 2`；`hist` ≥8 个且正确率 ≥0.75；
  2. **四个小游戏每一个**：至少 7 个证据，最近 7 个 ≥6 对，且最后一个对；
  3. **关键题型各自至少 1 个答对证据**：P1 `sub`；P2 `pair`；P3 `card`；P4 `giveN`；B1 `more`+`less`+`same`；B2 `match`；B3 `same`+`add`+`remove`；B4 `diff`；H1 `ord`；H2 `ord`+`card`；H3 `selfsplit`；H4 `hidden`；A1 `split2`；A2 `all`；A3 `plus`+`minus`；A4 `on`；X1 `target`；X2 `line`；X3 `ten`；X4 `hidden`；V1 `on`；V2 `build`+`name`；V3 `split10`；V4 `n2q`+`q2n`（数字关时 `d2q`+`q2d`，并在家长面板标注“点卡映射，未检验数字”）。
- **补测（R2-J01-b）**：某关的关键题型在当前等级（含家长设的下限）从不出现、又还没有证据时，本次第 2 轮以该题型最低可用等级出一题；补测题计入题型与该关证据，不进升级窗口、不触发升降级。
- **复测（R2-J03）**：答错后的复测与引导题保持同一题型与等级，只换数、位置与材料。
- 世界 3 需要世界 1 **和** 世界 2 都通过；之后逐个链式。解锁与通过都是粘性的。所有字段（含每关证据、题型、答题日志）持久化并在读取时逐项校验恢复。
- **大结局**：六个世界全部通过。
- **参与星**：每轮 +1，只增不减。

### 6.3 为什么猜不过去
- 固定位置：位置袋保证任意连续 7 题最多对 3 题 → 永远到不了“最近 7 个 ≥6 对”。
- 固定名次（永远最小/中间/最大）：名次发牌制保证每种名次 1/3（实测 33.3%），同理永远过不了。
- 固定语义（永远“一样多”、永远选布鲁伊）：语义袋 1/3，且关键题型各自要求答对（“永远一样多”拿不到 B3 的 `add`/`remove`）。
- 纯随机（1/3）：单关一个窗口“7 个里 ≥6 对”的概率 < 0.7%，还要四关同时成立、总正确率 ≥0.75、两个好会话、等级 ≥2。
- `test_pedagogy.py fixed`：7 种策略 × 2 个世界各玩 16 节，全部不通过、不解锁；`test_gates.py`/`test_pedagogy.py` 另验证全对能通过、需要四关、重载不丢证据。

## 7. 语音设计（R1-I01–I05）

### 7.1 两个通道与统一调度
| 请求 | 通道 | 规则 |
|---|---|---|
| 页面旁白（题面、总结、表扬、纠错） | 讲解 | 排队按顺序说完，句间 90 ms，队列只留最新 3 句；每句带**所属题目/会话**，入队与开口前淘汰过期的；等待它的代码只在所属题目存活时继续。 |
| 孩子输入 | 讲解 | 孩子的输入让旁白让路（唯一安全打断 `hush()`）；快进保留正在说的总结。 |
| 数词（孩子点数、系统复核） | 计数（mp3/WebAudio） | 最新数字优先、带请求序号与所属会话；解码晚到或会话已离开则丢弃；上下文挂起先 resume，失败回退；离开会话 `stop()`。 |
| 数词回退（mp3 缺失/解码失败） | 讲解引擎 | **受保护**：孩子点按、提交打断不了它；只有更新的数词能取代它；它排在队首。 |
| 首句补说（晚到的中文声音 / 首句未确认） | 讲解 | 只是“愿望”：每 400 ms 复查能否插话（引擎空闲、距上次请求 ≥1.5 s、3 s 节流），只在入口→地图这一代上下文内有效，离开即作废。 |

### 7.2 军规十条（逐条实现，`test_voice.py` 两引擎验收）
1. 入口 `click` 同步 `speak()` 第一句，**之前不 cancel**；同一手势里创建/resume AudioContext、播一帧无声 buffer、开始循环无声 `<audio>`。
2. 全应用唯一的 `cancelEngine()`（打断、看门狗、恢复都走它），每次记录禁播起点；`pump()` 保证 cancel→speak ≥150 ms。
3. 不信任 onstart/onend：本地请求与引擎状态分开；speak 后 450 ms、1100 ms 两次探测，**只确认当时仍在说的那一句**；兜底超时 `max(2500, 字数×380)`；本地超时后引擎仍忙 → 先等（≤1.2 s）→ 恢复 cancel，恢复后 2 s 内不再信任忙标志。
4. 每次 speak 前 `resume()`；回到前台时 resume 语音、AudioContext 与无声 audio。
5. WebAudio 惰性创建，每次手势内 resume 直到真正 running；首帧无声 buffer；每一步的结果与拒绝原因写入诊断日志；`unlocked` 跟随真实状态。
6. 中文声音评分（zh-CN、Enhanced/Premium/增强、婷婷/晓晓）；家长可选并持久化；utterance 引用上限 24。
7. 补说：见 7.1；“引擎有活动”“首句确认”“家长确认听见”三个独立状态。
8. 快速连点：讲解只留最新（队列 ≤3、过期淘汰），计数只播最新数字。
9. 每句记“确认 / 未确认”；连续 3 句未确认（或根本没有合成器）→ 地图出现 104 px 大喇叭、游戏中头像脉动，点它在手势内同步重说；排查文字只在家长面板。
10. 计数通道脱离 speechSynthesis（见 7.1）；看门狗每 1.2 s：引擎声称忙而本地无请求 ≥2.4 s → 走唯一 cancel 路径复位。

### 7.3 混音
讲解或计数出现时，环境声层自动降到 40%（ducking）；庆祝音效 4 套同音色变体轮换，不连续重复。

## 8. 视觉、动效、声音与“活的角色”

### 8.1 视觉语言
- 颜色：墨线 #2B2118、纸白 #FFF8EC、阳光黄 #FFC93C、珊瑚红 #FF6B5B、天蓝 #4FB3FF、草绿 #5CC46E、葡萄紫 #8E6CFF、橙 #FF9F43；每个世界一个主色（地图旗帜、加载画面、头像底色）。
- 圆角：28 / 18 / 全圆；阴影：统一“贴纸”阴影（墨线描边环 + 下沉阴影）；缓动：pop / glide / drop 三条。

### 8.5 小惊喜（只在题目之间或翻转时刻）

## 9. 技术架构
- 文件：`index.html`（内联 CSS/JS）、`sw.js`、`manifest.webmanifest`、`assets/{chars,thumbs,bg,bgthumb,props,isl,voice,splash}`、`assets/icon-*.png`。
- 逻辑舞台 1024×704 / 704×1024（contain 缩放 ≥1），背景 cover 铺满视口；`Stage.bgPoint(u,v)` 把背景归一化锚点换算成舞台坐标，前景元素据此定位。
- 模块：Store（容错存储层：所有读写 try/catch，失败用内存状态继续）、Voice/Count/Sfx、Input（四适配器 + 按住 + 统一 `__gesture`）、Stage、Actor、UI 表征组件、Session（轮/题/提示/奖励）、Mastery、Map、Loader、Parent、Finale、Games（24 个统一接口）。
- 测试钩子：`__ready`、`__q`（含 `phase`、`kind`、`answer`、`budget`、`ops`、`sceneLayout`、`cardLayouts`、`targets`、`plan`）、`__qn`、`__gesture(name,payload)`、`__fast`、`__speechLog`、`__state()`、`__go(world, game, level)`、`__res()`（资源计数：DOM 节点、活动动画、计时器、音频源）。
- 随机：每题种子派生自（节种子, 题号）；`?seed=` 可固定；同种子 + 同 payload → 同结果。
- **资源预算**：首屏（入口页）≤ 450 KB（压缩后的 HTML + logo + 6 张角色，实测约 397 KB）；单节 ≤ 1.3 MB；完整离线包 ≈ 9 MB（启动图 1.8 MB 不预缓存，按需缓存）。地图只解码 7 座岛（共约 480 KB）；离开世界时释放背景 `src`。
- **Service Worker（R2-F02）**：install 必须把核心文件与**全部**素材（逐个重试 3 次）写进新缓存，否则安装失败、旧版本继续服务；内容哈希相同的素材从旧缓存复制（`tools/gen_sw_list.py` 生成 `[url, hash]` 清单）；**一个版本 = 页面 + 全部素材**（R3-F02）：`VERSION` 是 index.html、manifest 与全部素材的哈希；页面与 manifest 只从**本版本**的缓存取（首访才走网络），`assets/*` 缓存优先；新版本在后台完整安装后**等待**，只在安全时刻（入口页、或切到后台）由页面请它接管并立即重载，页面与素材一起换；activate 时删旧缓存。首屏只加载入口所需（约 278 KB + 压缩后的 HTML 约 120 KB），地图素材在首屏可交互 1.5 s 后空闲预取，Service Worker 进入地图 2.5 s 后才注册。
