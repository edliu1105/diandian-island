# 用户体验抽查评审（R8，Fable 5.1 · high）

你是独立评审。对象：`index.html`（点点岛，给 3 岁半到 5 岁、不识字的中文孩子的 iPad 数学小游戏 PWA）。上一轮 R7 是 8/10。之后委托方提了一批较大的改动，这一轮抽查这些改动的**用户体验**，顺带看有没有退步。设计说明：`docs/DESIGN.md` §10（第二世界）和 §5.1（提示与答错）。

委托方这批要求（都已经做了，请检验做得好不好）：
1. **不能有重复逻辑的关卡**：第二世界原来 7 种玩法每种用在三个岛上（比如佩奇和汪汪队都有“照镜子”）。现在第二世界每个岛 4 关、共 28 关、28 种不同玩法，也不和第一世界的 24 种重复。
2. **每个岛的第四关是推理测验**：难度参照 Harker 一类学校的入学考试 / 资优学校的基准智商题（找双胞胎、藏图形、哪个不一样、图片记忆、矩阵、类比、推理赛跑），可以不用数字。
3. **铁则：星星只给孩子自己做对的题**。孩子卡住时只能语音鼓励、重说题目、提示“怎么做”，**永远不替孩子做、不揭示答案**，一直等。答错时就事论事地说哪里不对（不说“你错了”），然后**同一题再来**，不显示答案；这一题有过错就不给星。
4. **解锁**：一个岛的 4 关都玩过，而且前面每个岛的 4 关也都玩过，才开下一个岛（两片海都一样）；岛里一关一关开。
5. **自然的语音**：原来用设备的语音合成，像机器人。现在句子都预先用神经网络中文语音录好（`assets/voice/v/*.mp3`，列表 `assets/voice/bank.json`），播放录音；没有录音的句子才退回设备语音。你听不到声音，请用 `window.__speechLog`（说过的话）和 `window.__vmiss`（没有录音、退回设备语音的句子）检查覆盖率，并看录音播放会不会和动画、下一句抢话。

**评审方式：从用户体验角度抽查，不求全面（约 30–40 分钟）。评的是孩子和家长看到、听到、摸到的东西；代码只在发现问题时用来找原因。截图必须亲眼看。**

重点抽查：
1. 第二世界 28 关里抽 12–15 关（每个岛至少 2 关，第四关的推理测验至少抽 5 个），横屏 1180×820 和竖屏 820×1180 都看：任务能不能看懂（孩子不识字，靠语音和图）、目标够不够大、答对后揭晓有没有把道理讲清楚、答错后说的话是不是就事论事又不泄露答案、同一题再来时是否合理、难度是否合适（推理测验应明显更难但 4–5 岁的孩子做得到）。**最重要：真的没有两关是同一种逻辑吗？有没有哪关看起来和别的关（包括第一世界）其实是同一回事？**
2. 铁则：故意不操作 60 秒以上，确认没有任何替孩子做的动作、没有小手点在正确答案上，只有鼓励和重说；答错一次再答对，确认没有星星。
3. 解锁：造存档验证上面第 4 条。
4. 语音覆盖：玩过的关卡里有多少句子退回了设备语音（`window.__vmiss`）。
5. 视觉 bug：被挡住、裁切、重叠、错位、看不清。
